# 02 — Product Vision

## What this is

An AI-powered Decision Operating System. The product reduces cognitive load, anticipates critical moments, and guides the user toward the next best decision — starting in the health and daily-execution domain (training, nutrition, sleep, recovery, work-life balance).

## Why it exists

Most people already know what they should do — eat better, train, sleep more, stop ordering takeout, drink more water. Knowledge is not the problem; execution is. The gap between knowing and doing appears hundreds of times a week. Project Rebuild exists to close that gap.

## The core loop

```
Context → Decision → Intervention → User response → Learning
```

Concretely, for the current MVP:

```
Calendar context → Decision generation → Intervention → User action → Feedback
```

Context includes calendar events, free time windows, sleep/energy state, and known constraints. The system identifies the decisions that matter most today, intervenes before a poor decision happens (not after), and learns from accepted, completed, skipped, and edited outcomes.

## The product hypothesis (current MVP)

Using calendar context, can the system recommend timely actions that improve the user's daily decisions?

Nothing else matters until this is proven for the founder, the first user.

## Long-term vision

The same core Decision Engine may later extend beyond health to productivity, finances, parenting, learning, and relationships. Health is the first domain, not the only one. The company is building a system that reduces cognitive load and helps people make better decisions when those decisions matter most — not another health tracker.
